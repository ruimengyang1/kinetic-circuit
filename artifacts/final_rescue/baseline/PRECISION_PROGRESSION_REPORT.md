# Precision / Progression — 玩家反馈后的修订报告

上一版被实际玩家评价为：策略深度没有增长、难度没有增长、不够好玩。
本报告取代上一版的乐观评估。旧实现、旧报告和录像保留在
`artifacts/precision_progression/feedback_baseline/`，最早的审计保留在
`baseline/`。本轮修改前重新可视运行了被否定的版本，并先在
`PRECISION_PROGRESSION_PLAN.md` 追加了批判性审计与修订方案。

上一版的问题很具体：四关都只有两次冲刺，建立一个正确状态后就可以
永久离开 Can。L4 给最后一次冲刺附加了开门效果，却没有引入新的状态规划。
通关更快、标题叫“Combination”，都不能证明策略更深。

本轮可试玩实现、录像和物理验证已准备好。**是否更好玩、难度是否自然增长，
仍须实际玩家判断；不以脚本通过宣布这三个反馈已经解决。**

## 改动的核心

- 不变的基础：同样的方向引诱、重量接触、连续激光、光学接收器、移动平台、
  力冲击门；没有新增能力、危险物种或完成计数器。
- L2 开始，“有用状态”必须被花掉：先把登乘平台降下来，登上之后再移走 Can。
  移走使平台带人上升，下一个 Can 端点维持另一段横渡。
- L3 把同一模型变成两束用途不同、角度窗口分离的光学准备。稳妥玩法先冻结
  登乘状态再恢复旋转；熟练玩法提前登乘第一束光的经过状态，直接准备第二束。
- L4 同时要求登乘高度、正确光束、开门和最终重量。提前开门与保留最后开门
  会产生不同返回位置，需要不同的撤离提前量。
- Can 的位置与玩家自己的位置都必须被规划。没有用隐藏条件强制步骤数量。

## L1 — Direction

| 要求 | 本轮状态 |
|---|---|
| 上轮问题 | 基础方向教学尚可；不再随机改动它。 |
| 新学习目标 | 自己的位置选择意图，白色锁定后方向不再改变。 |
| 继承知识 | 无，课程起点。 |
| 新要求 | 右引打开挡门，左引抬升服务平台；两次相反引诱。 |
| 执行难度 | 低，宽台阶和普通跳跃，不强制反弹。 |
| 时机难度 | 低，只需读锁定并离开接触路径。 |
| 偶然完成修复 | 原有门、高度与实际出口地面保留；原地等待不会开始冲刺。 |
| 确定性 | 已有稳定搜索、固定行程、真实碰撞停止、无滑行保持。 |
| 预期新手 | 看一次结果，再换边应用同一规则。 |
| 预期熟练玩家 | 第一冲击恢复期间准备反向引诱，乘平台连续登上上层。 |

## L2 — Position

| 要求 | 本轮状态 |
|---|---|
| 上轮问题 | 只需把 Can 留在一个踏板上，之后不再考虑它。端点的价值无需被花掉。 |
| 新学习目标 | 不只关心 Can 的终点；还要在放弃当前状态前安排好自己的位置。 |
| 继承知识 | L1 的同一挡门、方向承诺和反向引诱。 |
| 新要求 | 右击门得到约 x220 起点；左停 x24 降下登乘平台；登乘后右停 x272，一边让所乘平台上升，一边维持横渡。 |
| 执行难度 | 低到中，降到 y281 的宽平台可直接进入，没加入激光或精细跳跃。 |
| 时机难度 | 低，登乘状态可稳定保持，正确顺序比速度更重要。 |
| 偶然完成修复 | 只有横渡就绪不能取得上层高度；提前从别处调用 Can 会把登乘平台空着升起。 |
| 确定性 | 三个可读端点与重量接触持续控制机器；修复从端点出发立即停止的 Can 边界错误。 |
| 预期新手 | 观察平台为什么先下降，意识到应先上车；误序后返回旧端点再做。 |
| 预期熟练玩家 | 准备下降中的登乘位置，Can 离开时已经登乘，直接利用下一端点的横渡。 |

输入式误序演示：先把 x272 横渡准备好但自己仍在下方，不能完成；
左回 x24 恢复登乘，再正确右引，5 次冲刺无伤完成。两次修正来自规划错误，
不是随机碰撞，也不需要重开全流程。

## L3 — Timing

| 要求 | 本轮状态 |
|---|---|
| 上轮问题 | 一次光束冻结便结束；没有后续状态必须依赖此前准备。 |
| 新学习目标 | 先取得登乘位置，再提前准备第二束光；读两次连续状态而不是等一个答案角度。 |
| 继承知识 | L1 的承诺方向；L2 的“先登乘，再花掉机器状态”与稳定重量端点。 |
| 新要求 | x338 重量转动激光。登乘接收器降低平台；离开该束光时升起已登乘的玩家；第二接收器持续供应横渡。 |
| 执行难度 | 中，宽台阶、140 px 登乘平台和普通跳跃。平台与 Can 安全等候区重合约 40 px，避免先前意外的 10 px 卡点。 |
| 时机难度 | 中，14°/s；第一接收器约 1.82 s 的角度窗口，第二约 1.12 s。早/晚 4° 的稳妥和熟练路线都无伤完成。 |
| 偶然完成修复 | 第二光束单独不能提供登乘高度；第一束单独不能供应最终高度；短暂经过第二束也不足以抬高横渡。 |
| 确定性 | 反射相位和真实光照一致；检查冻结后的持续照射，不能把余热当成功。接收器吸收光束后，上层跳跃不再横穿有效射线。 |
| 预期新手 | 冻结第一束，观察、登乘、返回 Can，再提前冻结第二束；4 次冲刺。 |
| 预期熟练玩家 | 利用第一束经过时主动登乘、保持不触发 Can 的位置，直接提前冻结第二束；2 次冲刺。 |

两次冲刺的熟练方案被保留：它仍需要真正的登乘接收器、主动准备位置和
第二束的持续对准。禁止它只会变成强制计数，损害所要求的精通感。

## L4 — Combination

| 要求 | 本轮状态 |
|---|---|
| 上轮问题 | 与 L3 相同的一次冻结，只附加一个开门结果，规划负担几乎未增加。 |
| 新学习目标 | 方向、返回端点、撤离距离、自己的登乘位置和同时保留的最终状态一起规划。 |
| 继承知识 | L1 力冲击和锁定；L2 持续重量与放弃状态前登乘；L3 两阶段相位与提前量。 |
| 新要求 | 第一光束提供登乘；最终光束提供横渡；门要打开；Can 必须最终停约 x418 持续压住出口升降机。光束正确但重量错误仍失败。 |
| 执行难度 | 中，没有加快 Can 或缩小跳跃；两个宽登乘区域分别服务 x170 / x272 返回起点。 |
| 时机难度 | 中，反向 14°/s；登乘窗口约 1.47 s，横渡窗口约 1.17 s。不同起点需要不同提前量，合理早/晚 4° 均可完成。 |
| 偶然完成修复 | 只开门、只照准、只有上层高度都不足；提前开门后最终向左冻结，会留下未供能的出口平台。 |
| 确定性 | 已知 x272 / x24 / x418 / x170 端点，按实际清空重量范围的距离决定延迟，出口重量不锁存。门向下撤回，不遮挡正确光束。 |
| 预期新手 | 使用稳定的冻结/返回过程，并在最后选择能保持出口重量的右端点；4 次冲刺。 |
| 预期熟练玩家 | 主动接第一束经过状态；最终右引同时冻结第二束、开门、停稳供应出口升降机；2 次冲刺。 |

### 两种稳妥规划确实不同

| 规划 | Can 位置序列 | 后续影响 |
|---|---|---|
| 保留最后开门 | 24 → 272 → 24 → 272 → 418 | 右侧登乘；最后清空踏板约需走 43 px。 |
| 提前开门 | 24 → 272 → 418 → 170 → 418 | 左侧登乘；最后清空踏板约需走 145 px，必须更早开始。第一冻结也须保留足够后续旋转时间。 |

最终右引的撤离距离相差约 102 px，按固定冲刺速度相当于约 0.34 s、
4.8° 的相位差；提前开门还会暂时升起出口平台；返回 x170 又会释放这份重量，最后必须重新建立。
准备和恢复还需一起算入。现有领先标记根据实际位置/状态
显示这段延迟，没有新增角度吸附或隐藏自动解题。

## 前后关实际迁移

- **L1 → L2：**同样的右侧力冲击建立已知起点，再用左引。现在还要从
  有用端点出发建立下一端点，并在转换前登乘。
- **L2 → L3：**已理解机器的有效状态不是永久钥匙。光束像重量一样只在
  当前条件满足时控制平台；先把自己安置上去，再让条件变化带自己上升。
- **L3 → L4：**先准备登乘，再在目标到来之前启动撤离。现在撤离方向和
  返回起点还决定下一次提前量，以及能否同时供应最终重量。

L4 增加的是需要保留的信息和状态关系。执行面仍采用已知的宽平台与普通跳跃。
实际玩家是否感到“更难，但知道为什么”，留待新一轮试玩确认。

## 保留的精确性与修复

- 玩家：原有 0.11 s 土狼时间、0.12 s 缓冲、强空中控制和短制动保持；
  移动平台不会给离开时的跳跃附加速度，输入能穿过短 hit-stop。
- Can：0.50 s 跟踪预告、0.12 s 明确锁定、300 px/s / 248 px 确定行程、
  0.32 s 恢复保持。新修复端点起步时只检查前方边界。
- Boulder / Fan：当前四关继续没有冗余使用。保留的 Boulder actor 受控运动
  和真实冲击转移检查通过，不靠弹性反弹决定终点。
- 光学：两个实际接收器的角度窗口分离；只以真实照射判断稳定冻结。
  不把短暂余热视为持续解。收集器角色文字靠各自实体，避免顺序反转时混淆。
- 摄像机 / 反馈：全房间同屏、锁定音、冲击暂停/轻震动/粒子、短视觉回弹保持。
- 重试：R 保留已完成关卡，死亡至控制约 0.27 s；初始位置不自动行动。
- 空等：加快登乘平台行程，移动时间用于登乘、下一位置与相位阅读。
  两种完整演示都没有超过 2 s 的连续静止段；不把平台载人误计为等待。

## 验证范围

证据目录：`artifacts/precision_progression/revision/`。

- `systems.json`：47 项运动、缓冲、支撑、锁定、碰撞预览、两端起步、
  反射、重物和摄像机检查。
- `audit.json`：52 组浅层行为尝试，其中 48 组仅用玩家输入、4 组显式禁用 Can；
  另查出口接触、出口侧反弹、短暂最终光束、胜利、R 和死亡恢复。
  被测乱跳、持续右行、忽略 Can、单次引诱后前进等均不能完成。
- `dependencies.json`：显式设置“只有后面的状态已正确”的反事实几何检查。
  缺登乘状态、缺最终光束或缺最终重量都不能由后面的机器就绪代替。
- `planning_recovery.json`：仅用输入制造 L2 的先调用后登乘错误，正常返回、
  重新登乘并用 5 次冲刺无伤完成。
- `route_*offset*.json`：稳妥、提前开门与熟练方案的早/晚 4° 完成证据。
- `replay.json`：2129 帧开环输入回放；玩家、Can、平台、角度、全部机器的
  供能/占用/照射、关卡与模式逐帧一致。没有根据状态重新调整输入。
- `comparison.json` 与 `screenshots/`：路线差别和直接检视的原生画面。

## 验收边界

物理状态依赖、方向承诺、端点稳定、合理时机余量、正常路线和被测旁路已验证。
没有增加新主要机制，没有用完成标记、不可见墙或冲刺计数代替理解。
这些检查不能穷尽所有操作序列，也不能证明玩家动机、教学效果、乐趣或主观难度。

本轮针对三条实际反馈做了可试玩的结构修订；不宣称“测试通过，所以更有策略、
更难、更好玩”。尤其需要新的实际试玩确认：L2 的状态交接是否读得懂，
L3 的两阶段预判是否令人满足，L4 的不同端点是否形成有意义的计划。
